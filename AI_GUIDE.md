# AI Guide — writing .irl with LLMs 🤖🌱

.irl is designed to be **reliably generated by AI**: one grammar, one way to
say everything, deterministic parsing, machine-readable errors. This guide
is the canonical prompt context for code assistants.

## The one-paragraph spec for LLMs

> .irl is Python's words with C's braces. Statements end at a newline or an
> optional `;`. Blocks are `{ }`. Declare variables with `var`. Conditions
> take parentheses: `if (x > 1) { } elif (x > 0) { } else { }`. Loops:
> `while (c) { }` and `for (x in iterable) { }` with `break`/`continue`.
> Functions: `function f(a, b) { return a + b }` — prefix with `memo` to
> auto-cache. Print with `print(a, b, sep=" ")`. Read input:
> `var n = int(input("n: "))`. Strings double-quoted with `\n` escapes and
> f-strings `f"hi {name}"`. Data: lists `[1, 2]` and dicts `{"k": 1}` with
> methods (`.append`, `.keys`) and slicing `a[1:3]`. Imports:
> `import math` (math, random, time, datetime, json, string, statistics
> only) or `import "utils.irl"` for local files. Booleans `true`/`false`,
> null `none`. Comments `//` or `#`. No classes, no try/except, no lambdas
> in 2.1 — do not invent syntax.

## Rules that keep generated code valid

1. **Always declare before assign** — `x = 5` without `var x` is an error
2. **Parenthesize conditions** — `if x > 1 { }` is invalid; `if (x > 1) { }`
3. **Convert before mixing** — `"n: " + 5` is an error; use `str(5)`
4. **`print` is plain** — no emoji prefix in 2.1
5. **Braces are not optional** — no single-statement braces-less form
6. **Semicolons optional** — pick one style per file (the formatter will
   normalize once `irl fmt` ships)
7. **Legacy slang works but prefer standard names** — `snag/spill/bet/cap/
   grind/brb/task/fax/fake/fr/nah` are aliases, flagged by `irl lint` later

## Machine-readable validation (agent loop)

Validate generated code without running it:

```zsh
irl lang check gen.irl --json
```

```json
{
  "ok": false,
  "file": "gen.irl",
  "errors": [{"line": 3, "column": 5, "message": "Expected a variable name, got '='."}]
}
```

Feed `line`/`column`/`message` back to the model to self-correct. Exit code
is 0/1 for shell pipelines.

## Grammar for tooling

The full EBNF lives in the repo and is printable:

```zsh
irl lang spec --json
```

One deterministic grammar → deterministic ASTs → reliable refactoring. The
AST is JSON-dumpable (DESIGN.md §9) so tools can transform code by tree,
not by regex.

## Notebook cells are prompts too

In `irl notebook`, markdown cells next to code cells work well as
few-shot context: put the intent above each cell, keep cells small,
export to `.irl` when the notebook graduates into a script.
